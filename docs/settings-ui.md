# Settings UI

Core 配置页的前端契约。后端分类描述见 `GET /api/settings/sections`；本文件只约束 `web/` 如何消费它。

## 分类注册

- 页面只渲染描述符列表，不在页面里再堆未注册的配置入口。
- 描述符字段：`id`、`title`、`owner`、`kind`（`core` | `plugin`）、`order`、`description`。插件描述符另有 `plugin_id`。
- Core id：`appearance`、`desktop`、`models`、`agent`、`roundtable`、`coding`、`compression`、`memory`、`system`。
- 插件 id：`plugin:<plugin_id>:<section_id 或 settings>`，不得与 Core id 冲突。
- 描述符不得携带任意 URL 或前端组件名。Core 分类走前端 registry；插件分类走通用 schema 编辑器，并使用已有 `/api/plugins` 列表与配置 API。
- 深链：`?tab=settings&section=<descriptor id>`。插件详情抽屉不再内嵌配置表单，只跳到该深链。

## 页面布局

- 保持原有居中单列折叠卡片，不改成左侧分类导航加右侧单页表单。统一代码注册、控件和保存不代表授权重做页面结构。
- 外观和模型默认展开；其余卡片独立折叠，可同时展开多个。折叠仅隐藏内容，编辑器与草稿保持挂载。
- 深链自动展开并滚动定位对应卡片，其他分类继续保留；保存或加载错误自动展开对应卡片。
- 浏览器环境不展示仅适用于桌面应用的更新分类。模型数量与添加入口位于模型卡片标题栏。
- 保留分类图标原有的颜色区分，颜色只作为图标的辅助识别，不延伸到标题、卡片背景或配置行。

## 保存

- 页面滚动容器顶部有一条 sticky 保存/放弃工具栏，位于应用顶栏之下。
- 工具栏跟踪所有已挂载分类的脏状态。保存按分类独立提交，报告分类级错误，不宣称跨存储原子成功。
- 保存失败或保存过程中又改过的草稿必须保留。
- 主题立即生效，不进入脏状态。供应商创建/删除/拉取模型、桌面更新、清空插件已存配置是显式操作；供应商可编辑字段进入统一保存。

## 字段

- 布尔、数值、枚举、敏感、只读和多行控件复用 `settings/SettingsFieldControl.tsx`。
- 连续配置条目用同文件的 `SettingsFieldList` 包裹 `SettingsFieldRow`，沿用父卡片统一底色，以留白和低对比细分隔组织条目，标签与控件垂直对齐；不使用斑马纹或额外的内层框线。Core 配置、压缩、记忆及插件字段共享此规则；插件嵌套对象保留自己的字段分组。列表不裁切溢出，保证内联下拉菜单与聚焦环可见。
- 不展示仅复述分类标题的说明句；保留会影响配置含义或风险的帮助文案。
- 缺省值显示为当前值，不旁白“有默认值”。枚举用选择器。敏感字段用密码控件。
- 记忆分类消费 `GET/PUT /api/memory/settings` 的返回值，不在前端再写一套默认值。关闭主开关或外部记忆在插件缺失/失败时仍可保存。
- 记忆配置和插件配置写操作继续携带管理令牌；失败或停用的插件仍可在配置页修复。
- Schema 的 `deprecated: true` 字段仅保留旧配置的校验与迁移，不进入编辑表单；草稿保存仍保留原值。
- 插件有待重启变更时显示保存与生效的区别；记忆启用前须通过后端对当前插件状态及服务健康的校验。

## 回退

`/api/settings/sections` 不可用时，前端使用内置 Core 分类列表，不包含插件分类。
