# 资源广场 Core 客户端发布检查单

适用范围：单个 Skill（含多文件包）的资源发现、投稿、安装、更新、卸载、社区评价及账号私有反馈。共享界面由 Website 托管，Core 提供本地 API、账号会话和桥接。官网普通页面仅展示简要信息。

多文件回归需覆盖：默认 `.md` 白名单、关闭类型检查仍拒绝路径越界、附件完整性、准备后的包摘要、
更新清理旧附件、本地附件修改拒绝覆盖、失败恢复完整目录、旧单文件兼容。发布需要新版 Core 与官网配套；
桌面安装包重新分发和社区版同步仍按各自发布授权执行。

## 发布边界

- Website Worker、静态资源和兼容 D1 迁移按官网发布流程交付。
- Core 源码合并和本地构建通过，不代表桌面安装包已经发布，也不代表运行中的客户端已更新。
- Core 桌面安装包、公开 Community 仓库和托管 Engine 分别遵循自己的发布授权。仅为桌面资源广场新增桥接，不需要重启托管 Engine。
- 笔枢 Portal 接入和多文件依赖处理不在本阶段范围。

## 候选检查

1. 记录 Website 与 Core 的确切提交、私有交付 Change ID、支持的桥接 capabilities（能力列表）。确认 Website 服务端已支持这些方法后，再分发新客户端。
2. 运行 marketplace 相关 Python 测试、desktop 和 settings 测试、design contract、前端 lint 与 build。
3. 使用隔离账号签发器、SQLite/R2 测试存储和真实 HTTP，验证 Core 本地路由到 Worker 的发布、评价分页、具体评价举报、审核隐藏/恢复、作者删除及反馈已读流程。
4. 使用两端真实桥接实现验证新方法及旧宿主降级。删除评价必须经 Core 确认，取消不能触发写入；确认超过 30 秒仍可正常完成，页面销毁会取消尚未执行的确认；执行中断联只能提示结果待确认。429 的等待秒数必须到达界面。
5. 复核匿名、普通账号、作者、审核员的权限和账号切换隔离。确保隐藏原因只向本人和审核员展示，举报快照/内部处理说明不泄漏到公开页面或通知。
6. 检查重复提交、过期 revision（修订时间）、并发写入、限流恢复；隐藏或删除评价必须同时更新公开列表和评分统计。
7. 确认官网没有下载、评论、投稿管理入口。客户端未提供新 capability 时，相应写入控件不可用，旧有浏览路径仍可使用。
8. 核对本机 install → open → update → uninstall：下载成功不等于安装完成；只有写入安装目录、来源记录并持久化启用及自动注入设置后才算首次安装成功。更新保留用户设置；卸载仅删除对应本地安装、来源与配置，不影响线上资源。
9. 核对登录/账号切换与过期恢复：私有列表随身份失效，本机草稿按账号分区保留；过期 access token 仅允许在同一登录会话续期后重试；退出或重新登录后旧请求不得换用新会话写入，不可恢复时返回 `login_required`。
10. 核对作者 draft → preview → pinned publish → reject/withdraw → revision：预览摘要与投稿锁定同一批字节；撤回或拒绝后填写更高发布版本创建修订版，可以更换本地内容来源；失败不得清掉未确认草稿。
11. 检查本机真实安装/投稿的结构化操作日志只含 allowlisted `operation`、`result`、`error_code`、`duration_ms`，不含 token、正文、用户 ID、URL 或异常 repr。

## 获得客户端发布授权后

- 锁定签名安装包和更新清单，确认其来源为已验证 Core 提交，再执行相应分发流程。
- 验证实际客户端的登录/退出、页面切换、返回资源列表、分页、键盘焦点、窄窗口及长文本。浏览器或桌面 UI 验收需用户明确授权，未执行时如实记录。
- 执行经授权的真实账号链路，清楚区分隔离接口联调与真实桌面/生产账号验收。
- 记录安装包版本、更新清单、生效客户端和回退候选，补齐同一 Change ID 的运行验证证据。

## 回退

Core 新方法为可选能力；旧客户端保留旧路径。Website 的 0009 为增量迁移，不回删 schema（数据库结构）或举报审计数据。

发生社区隐藏操作后，不可直接回退到不识别隐藏字段的旧 Worker，否则可能重新公开已隐藏内容。此时应保持治理过滤逻辑并修复前进，或准备保留过滤的新回退候选；只有核实没有隐藏记录且没有其他兼容性风险时，才能使用旧 Worker 版本回退。
